这一版只做一件事:**让「凭据以后还能不能用」变成可验证的**,而不是靠感觉。

## 三个命令,回答三个不同的问题

| 问题 | 命令 |
|---|---|
| 这份备份**能恢复**吗? | `gen-keystore.sh --drill <凭据包> --record` |
| 本机这把**对不对**? | `gen-keystore.sh --manifest`(或 `--status`) |
| 我到底**有几份副本**? | `gen-keystore.sh --scan` |

`--drill` 在临时目录里走**完整的导入路径**(解码 → 解包 → 读密码 → 算指纹 → 对期望值),
全程不碰本机凭据;通过后把日期、位置、字节数记进 `signing-manifest.txt`。
`--status` 会显示「上次恢复演练 N 天前」,超过半年直接提醒 —— **备份会悄悄过期**,
不演练就不知道。

`--scan` 比内容哈希、也比标志行,所以改名、换扩展名都躲不掉;并且规定
**`dist/` 里最多保留一份导出**(每多一份就多一个泄露面)。

## 传得动,也验得了

凭据包的实际流转方式是**粘贴**或**文件消息**。这一版把两条路都做扎实了:

- **导出默认折行 76 列**。单行长行粘进终端会被 `MAX_CANON` 静默截断
  (实测 7001 字符只进来 4096),折行后实测 7393 字节进 / 7393 字节出完整无损。
- **粘贴容错**:折行(哪怕到 20 列)、发送者、时间戳、末尾粘在负载上的「已读」、
  BOM、CRLF 都能处理。但**验证是严格的** —— 真的解压、真的当 tar 打开、
  确认里面有两个文件;只看格式是不够的。
- **`--drill -`** 从 stdin 读,直接从聊天窗口粘进终端,不用先存文件。
- **`--label @文件`** 绕开传不了中文的 shell 边界(Windows PowerShell → WSL
  启动器会把中文参数写成乱码**且不报错**)。

## 一个更正

之前文档把飞书那份当成「粘贴的文本」来写,并据此给了一长串 `MAX_CANON` 的分析。
实际是**文件消息** —— 那条路不涉及终端,字节也是原样的。
文档已按事实改:文件消息是**更好的**形式,推荐继续用它。

## 这一版修掉的一串 bug

全部是**真跑一遍**才暴露的,而且形状高度一致 ——
**输出/值可以是空的或错的,而下游当成成功处理**:

- 空 `version.properties` 被打了 ✅ 才推上去(发版把文件写成了 0 字节)
- 空指纹让 `grep -qF ""` **永远匹配** → 我上一版加的守护检查是个摆设
- 发布说明里的指纹字段在 CI 上是**空的**(证书信息走了 stderr,只抓 stdout 就没了)
- `--print-notes` 把构建进度和说明混在同一个 stdout → 据此生成的 Release 正文是脏的
- `--scan` 漏掉改了名的凭据包(`dist/signing-bundle.b64.bak`)
- `--scan` 返回 1 但脚本 `exit 0` —— 末尾那个 `if` 把安全检查的结果**吞掉了**

对策也是一条:**给数据流和诊断流划清边界,并在边界上验内容,而不是验退出码。**
