# docs/releases/ — 可选的手写版发布说明

CI 发版时,如果这个目录里存在 `<version>.md`,它的内容会作为 GitHub Release
说明的**开头**,后面再接自动生成的部分(附件表 / 签名指纹 / 安装 / 变更列表)。

```
docs/releases/
├── README.md      ← 本文件
└── 0.3.0.md       ← 想写就写,文件名必须正好是版本号
```

## 什么时候值得写

自动生成的说明已经包含:附件表、**签名证书指纹**、安装命令、`上一个tag..本版本`
的变更列表、以及「包来自 tag 检出」的声明。对日常发版够用了。

值得手写的场合:

- 这一版有**行为变化**要讲清楚(不是「加了什么」而是「用起来什么地方不一样了」)
- 有**迁移动作**(比如要求用户先卸载、或者配置要改)
- 有**已知问题**或绕行方案
- 面向的是不看你 commit log 的人

## 写法

跟着版本号一起提交(这样它就在那个 tag 里,CI 能读到):

```bash
$EDITOR docs/releases/0.3.0.md
git add docs/releases/0.3.0.md
git commit -m "docs(release): 0.3.0 发布说明"
git push
bash tools/tag-release.sh            # tag 名取 version.properties
```

不用加一级标题 —— CI 会用版本号当 Release 标题,正文直接从这个文件的内容开始。
文件末尾不用写「完整变更」之类的,自动部分会补。

## 不写会怎样

不会失败,CI 会自动生成一份完整的说明。这个目录纯粹是给「想说清楚」留的位置。
